# 日常 · 求职助手 0.5.1

手机继续使用「日常」原生 App，Windows 电脑提供私人岗位、招聘线索报告、材料版本和申请记录。所有资料保存在电脑的 `data/career-private/assistant.sqlite`，不写入公开岗位信息流。源码包不包含简历、报告、服务令牌或浏览器登录会话。

## 启动与连接

1. 安装 Node.js 24.15 或更新版本。日常使用可双击 `scripts/start-career-background.cmd`，服务在后台运行，重复启动会检查现有服务。该方式不设置开机自启，重启电脑后需要再次启动。调试时也可运行 `npm run career` 或双击 `scripts/start-career.cmd`，关闭调试窗口即停止该服务。默认只监听 `127.0.0.1:4176`。
2. 服务首次运行生成 `data/career-private/token.txt`。请把该令牌作为私人连接凭据保管。
3. 电脑和 iPhone 安装 Tailscale 并登录同一账号。运行 `powershell -File scripts/setup-career-remote.ps1` 检查状态，再运行同一命令加 `-Enable` 配置私人 HTTPS 服务。需要先完成 Tailscale 登录与 HTTPS 授权。
4. 在 App 底栏「求职」右上角打开设置，填写 Tailscale HTTPS 根地址（不加 `/v1/career` 或 `/v2/career`）与服务令牌，点击「保存并连接」。旧版钥匙串中的地址和令牌会继续使用。
5. 电脑浏览器打开 `http://127.0.0.1:4176/career`，用同一令牌解锁工作台。在「来源与报告」预览旧资料并迁移，迁移前会备份数据库。手机的旧收藏与跟进会迁入统一缓存并等待同步；原缓存文件保留。

每日北京时间 09:00 增量发现；当天 09:00 后启动会补做一次。也可手动刷新，刷新至少间隔一分钟。所有目标停用时不采集。首次调试可运行 `node scripts/career-server.cjs --no-schedule`，避免启动时采集。

浏览器采集依赖原有采集环境与独立会话；新电脑需要 Microsoft Edge、Playwright 运行环境并完成各平台登录。不会复制普通浏览器的 Cookie。登录、验证码或页面异常会暂停对应来源，其他已保存资料仍可查看。

### iPhone 真机连接验收

1. 在 iPhone 的 Tailscale 中登录与电脑相同的账号，允许系统添加 VPN 配置，并确认已连接。电脑需要开机且没有进入睡眠。
2. 按上面的 App 设置保存地址与令牌。若提示钥匙串保存失败，记录原始错误；这与网络连接失败分开检查。
3. 关闭 iPhone 的 Wi-Fi，保留蜂窝网络与 Tailscale 连接，打开底栏「求职」，点击同步。核对岗位数量、来源状态和报告执行时间，不能仅用 Safari 能打开页面代替 App 验收。
4. 将一个真实岗位收藏，退出助手再重新打开，检查收藏保留。此操作不投递简历。
5. 暂时断开 iPhone 的 Tailscale，再重新打开助手，检查页面可立即浏览，收藏、跟进和面试可保存在手机，显示待同步数量；材料审核不可批准。随后恢复 Tailscale，点击同步，检查队列清空。有同字段冲突时，明确选择手机或电脑版本。
6. 在岗位详情安排面试，检查「计划」出现对应日程；改期后更新同一条，重启不重复。关闭面试开关后对应日程取消。提醒需在求职设置主动开启。

后台启动方式会在私人目录记录 `connections.jsonl`，仅含请求时间、固定接口类别、状态码、客户端类别与对端地址，用于和手机操作时间交叉核对；不记录令牌、查询参数、表单正文或岗位内容。日志滚动保留至多两份，每份约 1 MB。此诊断文件不应上传公开仓库。电脑本机测试通过不代表手机或蜂窝网络验证通过。

## 手机与电脑分工

底栏为「今天、账本、计划、求职、我的」。运动入口在「今天」与「我的」。求职只有一套岗位、收藏和公司入口；「机会」用于筛选与收藏，「进度」显示待审批、提醒和面试，「报告」保存小红书招聘线索及历史具身观察。手机不编辑简历、原始 JSON 表单或执行投递。

电脑工作台负责真实材料及 PDF 版本、逐字段申请准备、差异与历史版本、模型建议、来源任务和获准后的执行。没有通过真实验证的投递能力不会提供执行按钮。

### 查看机会、检索与跳转

右上角同步和下拉刷新读取电脑已有结果；“查找新机会”向电脑发起一次有预算的增量检索。页面显示任务状态、最近检索时间、岗位及相关线索的新增和变化数量。读取帖子数见报告，求职帖、过期内容等不计入新增相关线索。没有新结果时不随机打乱推荐。BOSS 自动采集尚未通过验证，仍使用电脑扩展预览、导入；手动检索不会自动启用该能力。

“优先查看”按职位标题和方向、城市、明确的实习条件及新增或内容变化排序。只有正文泛泛提及“机器人”的岗位留在待核查区；标题明确相关的实习列表卡片可以优先展示，但不会因此宣称已读完整正文或满足全部资格。已关闭及超过 30 天未核查的岗位不能进入优先区。连续复查没有内容变化时，不重写发现时间；可切换“最新发现／变化”查看各来源近期进入库中的机会。

岗位卡片保留公司、职位、完整地点和简短理由，直接提供原平台入口；已保存的正文折叠在详情里。小红书使用官方文档中的 `xhsdiscover://item/<note_id>` 路由；网页备用入口保留原链接访问参数。BOSS 使用原始岗位 HTTPS 链接尝试系统 Universal Link，系统未接收时打开网页。右侧菜单可随时选择网页、复制原链接或复制标题。系统接受跳转不代表平台已显示具体帖子，实际到达详情仍需 iPhone 验收。

跳转依据：[小红书官方 Deeplink 文档](https://pages.xiaohongshu.com/activity/deeplink)、[Apple Universal Link 打开规则](https://developer.apple.com/documentation/uikit/uiapplication/openexternalurloptionskey/universallinksonly)。

手机启动先读取独立缓存，单次网络请求最多 12 秒，并在离开时取消；本机数据库读写和网络解码不在主界面线程执行。数据文件 `mobile-v3.json` 包括待同步修改，会进入 App 完整备份。审批不进入离线队列。

## 岗位与线索

- 岗位按目标显示精准推荐和拓展机会；未知学历、到岗天数等条件保持未知。全职岗位不会被标成精准实习。
- 目前实习僧使用公开搜索页面与有限详情读取，企业官网使用专用适配器或结构化招聘内容；不能读取的动态页面显示未完成。字体混淆字段不猜测。
- 小红书默认每轮最多读取 30 篇新帖，近 90 天为范围、近 30 天优先；未知日期单独标注，不以首次发现时间替代发布日期。默认不采集评论、不保存图片。
- 主报告排除求捞、普通经历分享和培训推广。公司、条件只从明确文字提取；身份与招聘有效性仍需用户核实。图片内容未识别时提示查看原帖。
- 报告突出新增及变化，每轮优先线索最多 10 条；最近 10 轮完整报告随快照缓存，已打开的历史报告也缓存（总共最多 60 轮）。没有新增只描述本次有限检索。收藏且未关闭的帖子每周最多复查 10 篇。
- 线索可以转为待核查机会，再关联正式岗位，不会触发投递。

## BOSS 当前页辅助导入

自动浏览器遇到登录或空白页时，可尝试辅助扩展：在 Edge/Chrome 扩展管理页开启开发者模式，加载 `extensions/career-capture` 文件夹。在扩展中填写本机服务令牌，打开真实招聘页面，点击读取、检查预览，再导入。

扩展仅在本人点击后读取当前可见的 BOSS 或实习僧页面；没有自动打招呼或投递功能。网页布局可能变化，当前页导入也会标为有限范围。扩展稳定 ID 为 `hlmdaklafhleodnklhdbkbjmkbkfmgpc`；服务只允许该扩展来源与本机界面。扩展真实账号读取尚待单独验收。

## 材料与审核

保存真实经历文本与可选 PDF（不超过 2 MB），每次保存形成不可变版本。页面展示修改差异和历史版本。准备申请后核对岗位、材料、附件、表单和动作，再批准。

批准绑定岗位内容、材料版本、表单内容及操作类型；发生变化必须重新审核。执行状态先写入数据库；未知结果、重启中断均停止自动重试。人工跟踪区分打招呼、发送简历、正式提交和面试。

当前没有通过真实投递验证的生产适配器，因此自动执行保持不可用。可以准备、审核材料，再打开原始页面完成操作并记录结果。测试中的模拟适配器不代表生产平台具备投递能力。

本机 Codex 使用已经登录的 ChatGPT 账号，结构化输出会校验并按输入缓存。模型只给匹配理由和材料建议，不能提交申请；额度不足时保留规则结果，不切换付费 API。在电脑岗位详情点击分析按钮发起分析。

## 备份与接口

App 的完整备份带上求职画像和本机阅读缓存；电脑端资料可在工作台创建数据库备份，完整 JSON 导入导出保留 API。恢复合并同 ID 记录，恢复前自动生成 SQLite 备份，历史批准失效。恢复不会导入服务令牌或登录会话。手机离线可读缓存、收藏、标记线索和记录跟进；本机修改原子保存、按操作编号防重同步，同字段冲突需要本人选择。审批始终在线校验，执行在电脑工作台完成。

所有 `/v2/career` 接口均要求 `Authorization: Bearer <个人令牌>`。保留旧 `/v1/career` 接口。主要资源：

| 资源 | 操作 |
| --- | --- |
| snapshot、profiles、jobs、sources | 状态、目标档案和岗位 |
| leads、reports、opportunities | 线索状态、报告与待核查机会 |
| materials、materialVersions | 真实材料及历史版本 |
| applications、approve、execute、status | 申请、审核、受限执行与人工跟踪 |
| sync | 离线收藏、线索标记、跟进及面试的幂等同步与冲突检测 |
| applications/:id/review、request-changes | 绑定版本的材料及 PDF 预览、退回修改 |
| tasks、refresh、ai | 任务、发现与 Codex 分析 |
| migration、backup、export、restore | 迁移预览、备份与恢复 |

## 验证范围

2026-10-19 本机真实只读验证：实习僧检索取得 5 个岗位卡片、读取 2 个详情；小红书一个关键词、一次滚动、读取 3 篇正文；宇树官网读取到 13 个岗位。BOSS 自动读取遇到空白页，未算成功。Codex 已用不含私人经历的测试材料完成一次结构化分析。

上述数字是有限采样，不代表全部岗位或招聘仍有效。0.4.0 已完成真实 iPhone 蜂窝网络连接，但用户发现离线缓存卡住。0.5.0 重写缓存与网络请求后，用户已确认旧数据保留、蜂窝同步、离线浏览和收藏、恢复同步，以及面试新增、改期、重启保留和取消。0.5.1 的推荐与检索改动已通过服务层验证；本轮真实检索新增 1 条岗位、更新 2 条岗位，从新读取的 30 篇帖子中筛出 20 条相关线索，部分来源未完成。外部 App 详情跳转须在新版本上单独真机验收。iOS 编译、UI 测试以对应 GitHub Actions 的实际结果为准。

本地检查：`npm test`；助手专用检查：`npm run career:assistant:test`。真实读取探针：`node scripts/career-assistant-live-check.cjs shixiseng`（也支持 `boss`、`xiaohongshu`），只读取，不发送信息或申请。
