# 计划助手 · 0.3.1

计划页的「帮我安排」将自然语言转成可编辑的出行需求，查询真实高德地点及路线，让配置的模型比较路线、解释推荐理由和取舍，再生成出发和活动两段日程。选择具体地点、路线并确认预览之后才保存；不会自行改动已有日程。

## 配置

在设置 → 配置智能规划，或计划助手右上角设置中填写：

- 高德开放平台申请的 **Web 服务 API Key**；iOS SDK Key 不能替代 Web 服务 Key。实际接口权限和额度以你的高德账号为准。
- 可选的模型接口：兼容 Chat Completions 的 HTTPS 服务地址、模型名称和 API Key。地址可以以 `/v1` 或 `/chat/completions` 结尾。仅有聊天产品会员不代表拥有 API 使用额度。
- 常用城市、明确的默认出发地点、交通偏好、活动时长和提前缓冲分钟数。

密钥在手机系统钥匙串中保存，不写入账本或备份；换签名身份或设备后可能需要重新填写。无需电脑接收服务。模型未配置时可以手动填写同一安排表单；地图查询仍需要有效高德 Key。

没有模型或高德账号时，也可以在「帮我安排」填写活动名称、地点、开始时间和时长，点击「手动保存普通日程」并确认。它只保存一项普通活动，沿用现有日历同步设置，不调用外部接口、不生成交通路线，也不推算出发时间。

## 使用

1. 输入例如「明天晚上六点半，从家去青岛市南区某家餐馆，坐地铁，用餐两小时」，实际使用时补上餐馆名称。
2. 点击「理解我的安排」，检查识别结果并补齐地点、日期、到达时间。未说明的值只在可编辑表单中显示默认值，不会自动创建日程。
3. 分别查询并选择出发地、目的地，确认具体门店或小区，避免重名。
4. 可填写「路线偏好」，如尽量省时或少走路；查询高德实际返回的方案，最多展示三条，有多少展示多少。可切换驾车、公交／地铁、步行或骑行后重新查询。
5. 配置模型时，查询路线后会自动计算各方案时间、检查冲突，再由模型给出整体推荐与每条路线的优点、取舍和注意事项。只有一条实际路线也能分析；费用、步行或换乘信息缺失时保持未知。有仍可出发且无已知冲突的方案时，模型不能推荐已过出发时间或有冲突的其他方案。
6. 可以「采用模型推荐」，也可自行选择其他路线。分析失败会保留真实地图路线，并允许重试或手动选择；修改需求、地点、交通方式、日期、缓冲或偏好会清除旧分析，需重新分析。查询和分析阶段都不写入日程。
7. 预览倒推出的出发时间和活动时间，重新检查冲突。最终保存前再读取最新日程、核实仍可出发；若预览之后出现新冲突或重叠日程改了时间，会再次提示确认。确认后保存到本地；已授权日历且默认日历可写时，同步到苹果日历并为两段安排设置开始前十分钟提醒。通知是否显示还取决于系统设置和专注模式。保存所选路线的模型说明，供以后查看及备份恢复。
8. 已保存行程可打开高德导航，或刷新当前路线参考。导航会重新计算路线；参考刷新不会修改已经确认的日程。已保存的模型说明是当时的参考，不会随着苹果日历编辑或交通变化自动更新。

## 信息和边界

理解需求时，模型接收此次输入和必要偏好；比较路线时，接收本次需求、起终点名称、高德路线估算、App 计算的时间及每条路线的冲突数量。不发送已有日程标题、备注、账本、短信、健康或完整日历。高德接收地点搜索词、城市和已选择起终点的坐标。日历冲突在手机本地计算。一次自然语言理解和一次路线分析分别调用模型服务，可能消耗账号额度；每次重试或重新分析也会请求接口。

模型输出经结构与路线 ID 检查，不能新增路线或改写 App 的计算时间；其文字解释仍可能出错，始终单独标为「模型分析参考」。未知费用、营业状态等不会成为自动执行依据。全部方案存在冲突或无法及时出发时，必须先调整时间或明确确认冲突；App 阻止保存已经来不及出发的安排。

此版本使用普通路线估算，不能准确预测明天的交通；已显示查询时间并预留缓冲，出发前可以重新查询。驾车过路费不是打车价格；未获得可靠费用时不推算。餐馆是否营业、排队或预约成功不由此版本保证，也不会自动预订或付款。

最终计划、路线参考、所选路线的模型说明、地点和偏好随完整备份保留。旧版 1–3 的账本和日程迁移到第 4 版快照；0.3.0 不含模型说明的行程仍可读取，不删除原有记录。系统日历外部调整或删除同步事件后，行程卡显示当前日程或仅保留原路线参考。

## 验证

包含脱敏接口响应夹具的网络解析检查、日期／缓冲／冲突／备份检查，以及模拟器和设备编译。真实高德和模型联调需要你自己的有效 Key；未提供密钥时不能声称已通过真实服务联调。截图预览数据仅在 Debug 构建加专用截图参数时可用，明确标注为测试数据，不查询、不保存；发布 IPA 不包含该路径。

## 0.3.5 灵活口述

简单日期、中文数字时刻先在本地识别。不说日期默认今天；不说时刻记全天，只说开始时间使用可调的 15–180 分钟默认时长。复杂表达调用模型，每次最多 1200 字、输出最多 1400 tokens（用量仍包括输入）；不发送历史账本和日程。同一输入再次记录或日历重试复用结果。结果显示服务返回的实际 token 用量。

模型设置新增 GET /models 查询，选择账号可用模型并保存。DeepSeek 的管理平台不是接口地址，官方接口地址是 https://api.deepseek.com。真实账号和日历权限需手机验收。
