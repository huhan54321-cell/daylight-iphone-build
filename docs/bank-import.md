# 银行通知、短信与微信动账截图

## 工行 App 动账通知（0.3.4）

首选自动接收来源改为工商银行 App 的「动账通知」。不要求短信末尾的银行署名，不设 10 元最低金额。校验实际通知标题必须为「动账通知」，正文必须完整包含四位卡尾号、交易时间、支出／收入／退款类型和唯一金额；活动标题、促销内容、验证码、失败交易、截断或拼接通知不自动入账。无法确认金额的输入保留待确认，不用余额代替消费金额。

配置：在支持通知触发的系统快捷指令中，新建「收到 App 通知」自动化，来源只选择工商银行 App，标题筛选「动账通知」。将输入的 **Title** 和 **Body** 分别传给日常的「接收工行动账通知」操作的「通知标题」和「通知正文」，通知编号留空。标题必须使用真实变量，不能固定填动账通知。App 没有直接读取其他 App 通知或历史消息的权限。iOS 18.2.1 没有这一触发器；[苹果事件触发器指南](https://support.apple.com/en-kg/guide/shortcuts/apd932ff833f/ios)列出 iOS 27 的通知触发功能，真实工行推送、锁屏及 Apple Watch 通知路由仍需手机验收。

开启设置中的「自动保存明确消费与充值转移」后，明确的消费和充值转移可保存；收入、退款、另一张银行卡需确认。通知涉及的同一交易按卡尾号、分钟、方向、金额和商户自动去重，不再增加待确认项；已知不同的余额或尾号区分为不同交易。同分钟、同商户、同金额而没有余额的重复通知按同一笔处理。配置通知自动化成功后停用旧短信自动化。旧短信入口和已有记录保留；两个入口收到同一笔时不会自动重复记账。

通知没有余额时，不虚构余额：先在账本设置工行卡起始余额和对应时间，此后已保存的银行收支更新估算余额。通知有交易后余额时使用银行报告的余额。漏掉一笔通知仍会影响估算，应定期校准。

账本新增「补录动账通知」，可以粘贴标题及正文核对后保存。自动化诊断记录来源、阶段和结果，不保留通知原文。解析与本地 UI 可由云端自动测试；银行推送到系统自动化的真实链路不等于模拟器测试。

## 原有短信与微信截图

App 解析金额没有 10 元下限，支持 0.01 元。银行没有发送的小额短信不会触发短信自动化；后续余额校准也不能还原缺失消费的商户、金额和时间。

## 截图补录

账本 → 识别微信动账截图 → 选择最多 20 张图片 → 逐笔核对 → 确认保存。

支持工行微信服务号「动账交易提醒」：完整卡片应含工行标题、借记卡尾号、交易时间、交易类型、出账或入账金额及账户余额。一张截图可以有多张卡片。图片在手机本地用 Apple Vision 识别，不发给模型或服务器；原图不写入 App 账本。只保存确认的结构化记录和脱敏后的识别内容。余额与交易金额分开读取，不拿余额替代消费。

可以修改金额、日期、类型、分类和余额。模糊数字不会自动猜测；卡片不完整、金额或日期不明确时提示重新截图。已存在的截图记录会跳过并提示，与短信或其他记录相近的交易默认不选中，只有确认是另一笔时才保存。重复判断并不能证明两笔一定相同，请核对原始记录。

当前工行余额按一张卡计算。不同卡的余额不能混用；可以取消「计入工行卡余额」，或分别处理同一张卡的截图。截图余额仅在确认保存后参与校准，不代表缺失的全部明细已补齐。

若同一分钟有多笔涉及截图的交易，不用截图导入顺序或随机标识判断最后一笔。原始余额保留供核对，余额显示使用更早的可靠余额加收支差额并标为估算；没有可靠起点时提示校准。后续明确的余额检查点或该分钟之后的手动校准可恢复正常显示。

## 漏记短信

账本 → 补录银行短信 → 粘贴完整工行交易短信 → 识别并核对 → 保存。请勿粘贴验证码。此入口不会直接自动保存，便于补录自动化失败的单笔。

设置 → 短信记账 → 最近短信接收：显示最近调用时间、阶段、结果及诊断代码，不保存正文、商户、卡号或自定义编号。若快捷指令根本没有调用 App，或者系统中断进程，诊断可能不更新。下一次失败时以完整快捷指令错误和这里的诊断一起排查。

接收时重新读取本地记录，解锁后可恢复先前暂时不可读的状态。文件损坏或仍受保护时继续拒绝覆盖，提示解锁、打开 App 或恢复备份。诊断不是可靠消息队列，失败的短信仍需补录或重新触发。

## 权限与范围

普通 iPhone App 无法通过申请一个权限直接读取微信的聊天或服务号内部记录；[Apple 的沙盒隔离说明](https://support.apple.com/en-euro/guide/security/sec15bfe098e/web)解释了 App 数据隔离。相册选择器只把用户选中的图片交给 App，截图 OCR 使用 [Apple Vision 文本识别](https://developer.apple.com/documentation/vision/recognizing-text-in-images)。

这条路线减少逐笔手动录入，但不能后台自动获得微信全部流水，也不能识别截图外、被裁切或未加载的消息。能否降低短信通知门槛，需要核实本人银行账户的信使设置，不承诺所有储蓄卡都可设为零。

升级前在设置导出完整备份，使用原签名身份和应用标识覆盖安装。新 OCR 与锁屏接收仍需要本人 iPhone 实测。

## 0.3.5 每日账本

账本默认按日，日视图不显示趋势；收支明细先显示最近 5 笔，可展开全部、再收起。补录入口移到底部。统计按全部筛选周期记录计算。商户关键词本地分类，餐饮词优先于交通词（地铁口炸串为餐饮），未知商户仍待分类，用户已明确设置的分类不改。历史待分类在读取及恢复备份时补齐，金额、ID 和余额不改变。
